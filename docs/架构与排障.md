## 数据与控制路径

```text
nic-1 (.3.1, DEV60) <---- Tofino1 ASIC ----> nic-2 (.3.2, DEV52)
                               ^
                       BFRT / 本机控制面
                               ^
                Flask 网页（选指纹、确认进程、遥测）
                               ^
                nic-2 p0f 采集器（独立令牌、心跳）
```

- `antiFpProbe.p4` 选择 Nmap 或 p0f 源码；每种模式分别编译，因此无需在切换时修改这个文件。
- `test_nmap/test.py` 保留原主动防御规则、ISN、TCP 选项和指纹热更新逻辑。
- `test_p0f/test.py` 与 `p0f_profile.py` 保留原被动指纹处理和参数规范化。
- `HTML/control_plane`、`HTML/p0f_control` 是网页适配层，复用上述模块，单独提供遥测、活动指纹位置和程序周期标识。
- `monitor/scan_monitor` 提供无指纹改写的监测转发，补齐原先在项目外的依赖。
- `scripts/build.py` 只编译和生成本地配置，`scripts/data.sh/control.sh` 负责有检查的手动启动；网页负责带人工确认的切换。

## Host seems down / ping 不通

`mass_dns` 只是 DNS 提示，不是 ping 全丢包的原因。依次检查：两端 enp5s0f1 是否存在、驱动是否归内核、IP 是否仍为业务地址、路由是否走业务网卡、ARP 是否解析、交换机两端是否 UP、DEV 映射是否匹配。

常见原因是别的吞吐实验把 NIC 绑定给 DPDK。此时交换机端口 UP、控制面 READY 仍可能正常，但 Linux 无法用该业务口收发。应由设备管理者协调并恢复正确驱动/地址；本包不会自动重绑定或写网络配置。

网页的“链路就绪”表示硬件端口状态连续确认，并不等同于两台 Linux 端到端可达。`doctor.py` 同样不会通过不受限 SSH 自动修改 NIC。用主机上的 `ip`、`ethtool`、`ping` 验证真实路径。

## Python 目录找不到 p4testutils

错误如 `install/lib/python3.10/site-packages/p4testutils/... not found`，通常是激活了错误的 Conda 环境，启动脚本按 Python 3.10 查找实际为 3.5 安装的 SDE 组件。

控制面入口会清除 `PYTHONHOME/PYTHONPATH`，优先 `/usr/bin`；网页使用独立 `.venv`。不要复制另一个 Python 版本的二进制扩展到错误目录。更换 SDE 时，重新核对其官方配套 Python 和 BFRT/PTF 依赖。

## 切换失败 / PID 未退出

网页在确认前后核对 PID、启动时间与命令行。它不会无条件 SIGKILL 或杀整个进程组。若进程未退出，查看 `HTML/runtime/control.log`、`data.log`；先定位具体阻塞，不要反复并发启动。

确认窗口过期、进程列表变化或 PID 被复用时，需重新准备并确认。构建缺失会在停止当前程序前报错。手动启动脚本默认拒绝已有数据面，不会替你停止别人运行的程序。

## 能显示 OS 名称是否等于成功

不等于。必须区分候选指纹、格式校验通过、控制面已下发、抓包字段匹配、探测器识别以及正常业务连接。Nmap 的时间戳时钟、IP-ID 序列、部分 U1 字段仍有覆盖限制；p0f 中无 TS 目标与当前预编译流程存在兼容性限制。

指纹库中同名 OS 的两个变体不能替代两次成功实验。正式比赛建议只演示自己已完整复测并保存记录的指纹。不要为了扩大展示数量把不兼容提示改为成功状态。

## 网页统计与时钟

Nmap 检测计数基于硬件规则匹配；会话数是聚合估计。p0f 是被动观测，仅在新的 TCP 握手中获取主要签名。两台机器应保持合理时钟同步，否则时间线可能看起来偏移。本包不改系统时钟。

## 停服与回滚

源码整理不覆盖原项目和原 SDK 编译产物。如新版演示失败，先明确退出新版控制面与数据面，再使用你原工程的已知流程恢复。不要同时运行两个目录里的控制面。网页单独停服不会修改 ASIC 当前程序。
