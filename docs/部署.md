# 部署与环境检查

[English](DEPLOYMENT_EN.md) | 简体中文

## 1. 硬件与三台主机

数据面必须运行在 **Tofino1 ASIC** 上，本项目验证环境为 SDE 9.7.0。SDK、驱动、固件和平台管理库由部署者按设备供应商要求安装，本包不提供这些组件。

| 主机 | 原实验管理地址（示例） | 业务地址 | 网卡/端口 | 用途 |
|---|---|---|---|---|
| Tofino1 | 192.168.30.252 | 无需配置业务 IP | 物理 10 ↔ DEV60；物理 9 ↔ DEV52 | 数据面、控制面、网页 |
| nic-1 | 192.168.30.130 | 192.168.3.1/24 | enp5s0f1，接物理 10 | Nmap 扫描、iperf 客户端 |
| nic-2 | 192.168.30.131 | 192.168.3.2/24 | enp5s0f1，接物理 9 | 被扫描主机、p0f、iperf 服务端 |

管理网络与业务网络不是一回事。管理地址用于 SSH/网页，不是 P4 程序生成的地址。不同交换机的逻辑端口可能不同，须在 `bf-sde.pm>` 中用 `show -a` 核对。当前控制面会把 DEV52、DEV60 设置为 100G、RS FEC、启用状态；这属于明确启动实验时的端口配置，不会自动修改 Linux 网卡驱动或 IP。

本版保留原实验业务地址、端口和 MAC 示例以避免改变算法。换拓扑时必须同步检查 `configs/*.txt`、两个控制面的端口/MAC 表、`monitor/scan_monitor/scan_monitor.p4`、HTML 两个控制面适配器和 p0f 采集过滤条件；只改部署 JSON 不会自动改 P4 转发关系。

## 2. 软件前提

| 位置 | 软件 | 说明 |
|---|---|---|
| Tofino1 | SDE 9.7.0、bf-p4c、bf_switchd、平台库 | 已能正常驱动本机 ASIC |
| Tofino1 | SDE 配套系统 Python | 原实验为 `/usr/bin/python3`，版本 3.5；含 BFRT/PTF 依赖 |
| Tofino1 | Python 3.9+、venv | 仅供 Flask 网页使用，不替换系统 Python |
| nic-1 | Nmap、iperf2、iproute2 | 原实验 Nmap 7.60；版本与 OS 数据库影响识别结果 |
| nic-2 | p0f 3.x、iperf2、iproute2 | p0f 输出需兼容 p0f 3 的文本格式 |

普通 Linux 主机可根据自己的发行版安装工具，例如 Ubuntu/Debian 的 `nmap`、`p0f`、`iperf` 包。`iperf3` 与这里的 `iperf` 命令不兼容。不要在交换机的系统 Python 环境全局升级依赖。

## 3. 只读检查 Linux 网卡

nic-1：

```bash
ip -br link show enp5s0f1
ip -4 addr show dev enp5s0f1
ip route get 192.168.3.2
ethtool -i enp5s0f1
ethtool enp5s0f1
```

nic-2：

```bash
ip -br link show enp5s0f1
ip -4 addr show dev enp5s0f1
ip route get 192.168.3.1
ethtool -i enp5s0f1
ethtool enp5s0f1
```

预期业务地址分别为 `.3.1/24`、`.3.2/24`，路由经业务网卡。若网卡被别的实验绑定给 DPDK，接口可能消失或内核没有业务 IP。先协调设备使用权再恢复；本包不会自动执行 `dpdk-devbind`、`ip addr`、路由或防火墙修改。

## 4. 初始化本地配置

登录 Tofino1，进入你收到的项目目录。不论该目录改成什么名字，下文的相对路径均不变。

```bash
export SDE=/root/bf-sde-9.7.0
/usr/bin/python3 scripts/configure.py --sde "$SDE"
```

脚本生成 `config/deployment.json` 及私有运行目录，复制两种模式各自的初始指纹。重复运行不会覆盖已经选定的活动指纹，但会同步 `configs` 中的转发表到 HTML 运行目录。不会启动程序、生成固定密码或修改 SDK。

如需内网访问网页：

```bash
/usr/bin/python3 scripts/configure.py --sde "$SDE" \
  --web-host 0.0.0.0 --web-port 5080 \
  --switch-address 192.168.30.252 --sensor-address 192.168.30.131
```

按实际管理地址替换。默认绑定 `127.0.0.1`；开放内网时只供可信隔离网络使用，不直接暴露公网。两种方式都保留令牌认证。脚本不修改防火墙或 SSH 配置。

## 5. 首次编译

先找本机已验证能启动硬件的 switchd 配置，确认其 `chip_list`、PCI 信息和平台代理正确。本实验机可用以下例子：

```bash
export PLATFORM_CONFIG="$SDE/install/share/p4/targets/tofino/antiFpProbe.conf"
/usr/bin/python3 scripts/build.py all --platform-config "$PLATFORM_CONFIG"
```

如果这份配置不存在，用本机已验证程序的配置替换。不要直接复制另一台机器的 PCI 路径。构建脚本只读取该文件，把本项目 P4 输出和其硬件部分组合成三份独立配置：

```text
build/nmap/antiFpProbe.conf
build/p0f/antiFpProbe_p0f.conf
build/monitor/scan_monitor.conf
```

Nmap 使用 `ENB_NMAP=1, ENB_P0F=0`；p0f 反之。都保留 `antiFpProbe` 程序名以兼容原 BFRT 表及控制面，但构建目录、运行配置分离。监测转发程序名为 `scan_monitor`。

构建不会执行 `make install`，不会覆盖 SDK 下已有程序，也不会加载 ASIC。编译日志位于各模式的 `compile.log`。只编译一个模式时把 `all` 换成 `nmap`、`p0f` 或 `monitor`。

## 6. 自检

```bash
/usr/bin/python3 scripts/doctor.py
```

检查 SDE、配套 Python/BFRT、三个构建配置及产物路径、初始指纹、网页端口。报告失败时先处理，不要直接启控制面。这个自检只读，不会停止其他进程；它不代替两台 NIC 的链路、IP、ARP 和 ping 验证。

## 7. 整个目录移动或改名后

源码无需改路径。重新设置 `SDE` 并初始化，再重写本地生成的绝对构建路径：

```bash
/usr/bin/python3 scripts/configure.py --sde "$SDE"
/usr/bin/python3 scripts/build.py all --config-only --platform-config "$PLATFORM_CONFIG"
/usr/bin/python3 scripts/doctor.py
```

`--config-only` 不重新编译；前提是原 `build/` 完整保留、SDK/硬件未变。只拿到公开源码的新机器须先正常编译。虚拟环境不保证可搬迁，目录移动后应重建 `.venv`。
