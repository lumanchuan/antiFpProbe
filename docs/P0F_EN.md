# p0f Passive-Fingerprint Defense: Manual Procedure

English | [简体中文](p0f.md)

Complete [deployment](DEPLOYMENT_EN.md) first. Unlike the Nmap experiment, **nic-1 initiates a TCP connection and p0f on nic-2 observes the client SYN**. p0f does not scan actively, and the SYN-ACK generated by nic-2 is not the client fingerprint modified by this mode.

## 1. Start the data plane on Tofino1

If you just completed an Nmap experiment, stop its control plane and data plane first, or finish the web console's confirmed mode-switch workflow. Two `antiFpProbe` control planes must not run at the same time.

In Tofino1 Terminal 1, enter the project root:

```bash
bash scripts/data.sh p0f
```

This command uses `build/p0f/antiFpProbe_p0f.conf`, preventing accidental use of the Nmap build output.

## 2. Start the control plane on Tofino1

In Tofino1 Terminal 2, enter the project root and wait for Terminal 1 to finish initialization:

```bash
bash scripts/control.sh p0f
```

Check the output for `P0F_READY`, the target OS, and port status. A running control plane does not prove that the Linux traffic path is reachable; still verify the interfaces and addresses on both hosts.

## 3. Start p0f on nic-2

In nic-2 Terminal 1:

```bash
p0f -i enp5s0f1 'tcp port 5001'
```

After p0f enters its main event loop, wait for traffic. This is a normal listening state; no new OS observation appears until a new TCP handshake occurs. Root privileges or equivalent packet-capture capability are required.

## 4. Start an iperf2 server on nic-2

In nic-2 Terminal 2:

```bash
iperf -s -B 192.168.3.2 -p 5001
```

If the port is occupied, inspect it with `ss -lntp` and do not terminate another user's service. This procedure requires iperf2.

## 5. Generate a new connection from nic-1

On nic-1:

```bash
iperf -c 192.168.3.2 -p 5001 -t 10 -b 1M -l 1024
```

Check both outcomes:

1. p0f on nic-2 reports the OS/raw signature in the `syn` direction from `.3.1` to `.3.2`, matching the active target fingerprint.
2. Both iperf client and server report real traffic. A p0f label without a working TCP connection is not a successful result.

For strict validation, capture the handshake on the receiving side with tcpdump and inspect TCP/IP checksums, TTL, window, and option layout. NIC checksum offload can change how checksums appear at a capture point, so do not draw conclusions from a sender-side warning alone.

## 6. Change the target fingerprint

The web console's p0f profile library provides selection, import, and actual deployment status. The manual active file is:

```text
HTML/runtime/p0f_state/fps.json
```

Optional examples are under `test_p0f/examples/`, and the installed profile library is under `HTML/profiles_p0f/`. Profiles with the same OS name can represent different signature variants; their presence does not prove that every variant has been validated.

```bash
cp /path/to/selected-p0f.json HTML/runtime/p0f_state/fps.json.next
/usr/bin/python3 -m json.tool HTML/runtime/p0f_state/fps.json.next >/dev/null
mv HTML/runtime/p0f_state/fps.json.next HTML/runtime/p0f_state/fps.json
```

Wait for the control plane to report that the new profile is active, then run the iperf command on nic-1 **again**. Fingerprint recognition primarily occurs during the handshake; editing JSON does not make an existing long-lived connection emit a new SYN.

Timestamp compatibility checks remain enabled. The current Linux-input transformation has a known checksum problem for some target signatures without TCP timestamps, so those profiles are not presented as verified working configurations. Do not bypass the check merely to increase the number of selectable profiles.

If you use the original `test_p0f/test.py` control plane instead of the web adapter, the active file is `test_p0f/fps.json`, and no HTML telemetry is produced. The recommended entry point is `scripts/control.sh p0f`.

## 7. Stop

Wait for the client to finish. Use Ctrl+C in the two nic-2 terminals to stop the p0f and iperf processes you started. On Tofino1, stop the control plane before the data plane. The web sensor is a separate process; see [HTML_EN.md](HTML_EN.md) for its lifecycle.
